# B2 · LZ4Inv v4 压缩器

> **结论先行**
>
> v4 把压缩率差距从 **+52.1% 收敛到 +1.2%**（124,038 vs 游戏 122,604），往返 **0 字节差异**。
> 但对某些小纹理仍不如游戏（如 9,792 字节的 logo：10,109 vs 9,646），这是 `compBI` 变大的直接原因。

**测试数据：** 真实 ASTC 纹理 1,048,576 字节（`UI_VFXbase` 的 `.resS`）

## B2.2 v4 的五个改进

```
1. HBITS 17 → 20（131k → 1M 哈希桶）
2. CHAIN 16 → 1024（匹配候选 ×64）
3. 匹配搜索改为【最近优先】（从链尾往前）
4. 快速排除：先比 src[ref+bestLen] 再全量 memcmp
5. lazy matching：若 ip+1 有更长匹配则跳过当前位置
```

## B2.3 可配置

```bash
# 默认（CHAIN=1024，最高压缩率）
tools/.efml4a-bin/lz4invcomp4 <in> <out>

# 快速模式（CHAIN=256，速度快 4 倍）
clang -O2 -DCHAIN=256 -o lz4invcomp4f lz4invcomp4.c
```

源码里：
```c
#ifndef HBITS
#define HBITS  20
#endif
#ifndef CHAIN
#define CHAIN  1024   /* 可 -DCHAIN=256 换取速度 */
#endif
```

## B2.6 ⚠️ 已知不足

```
ui_main_menu_logo_icon (9,792 字节):
  游戏: comp = 9,646
  v4:   comp = 10,109   ← 比游戏大 4.8%

⇒ 直接导致 compBI 从 101 → 102
⇒ 游戏跳过该 .ab（见 C2）
```

**改进方向：**
- CHAIN=2048 或 4096
- optimal parsing（多次尝试选最优）
- 或对小块数据用更优的 match 策略
